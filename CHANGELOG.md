# ProductFlow AI — Changelog

## v1.7.0

- CRM-справочник клиентов/контрагентов с Web, REST, MCP и Telegram доступом.
- Привязка заказа клиента к `customer_code` с сохранением совместимости со свободным `customer_name`.
- Статусы заказа расширены: `new`, `reserved`, `processing`, `completed`, `cancelled`.
- Резервирование товара на MAIN без уменьшения физического остатка.
- `product_availability`: физически / в резерве / доступно к продаже.
- Защита резерва от других заказов и ручных отрицательных складских операций.
- Снятие резерва до первой отгрузки.
- Частичная и полная отгрузка с автоматическим переходом `processing → completed`.
- Клиентская карточка: количество заказов, завершённые заказы, выручка, валовая прибыль, история.
- Web Admin: раздел Клиенты и workflow заказа с резервом/обработкой/частичной отгрузкой.
- REST API: customers, availability, reserve/release/processing/ship endpoints.
- MCP расширен до 39 tools.

## v1.6.0

- Полноценное управление каталогом из Web: создание товара, карточка, редактирование, архив/восстановление.
- Складская операция прямо из карточки товара.
- Web CRUD поставщиков: создание, редактирование, активация/архив.
- Web-черновики закупок: создание, редактирование позиций/цен/поставщика, приёмка и отмена.
- Web-черновики заказов клиентов: создание, редактирование позиций/цен, завершение продажи и отмена.
- Проведённые закупки и продажи блокируются от редактирования для сохранения целостности истории.
- REST API расширен GET/PATCH для поставщиков, закупок и продаж, а также cancel endpoints.
- Все новые Web/API write-операции фиксируются в audit log.

## v1.5.0

- Web Admin Dashboard на отдельном systemd-сервисе.
- REST API v1 с Bearer-аутентификацией.
- Безопасный localhost-only bind по умолчанию.
- Автогенерация Web admin password, API key и session secret при обновлении.
- Товары, склады, поставщики, закупки, продажи и аудит доступны в Web/API.
- API write-операции используют существующие repository-транзакции и записываются в audit log.
- `/label SKU` теперь формирует одну товарную этикетку с QR + Code128.
- `/audit` показывает больше контекста операции.
- Убраны дубли Telegram BotCommand.

# Changelog

## 1.4.1

- Исправлена загрузка Settings: удалено устаревшее обязательное поле `rate_limit_per_minute`.
- Генерация Code128 PNG переведена с ReportLab/renderPM на чистый Pillow, без Cairo/native backend.
- Удалена зависимость ReportLab для штрихкодов.

## 1.4.0

- Мультисклад: `MAIN` + дополнительные склады, распределение остатков и перемещения.
- Текущий остаток v1.3.x автоматически мигрирует в `MAIN`.
- Закупки и продажи синхронизированы с основным складом.
- QR-коды и сканируемые Code128 PNG для карточек товара.
- Административный аудит с Telegram ID, ролью, действием, результатом и деталями.
- `/audit` доступен только admin; audit MCP tools скрыты от AI.
- Rate limit запросов пользователя (`SECURITY_RATE_LIMIT_PER_MINUTE`).
- Улучшена нормализация Telegram-разметки и HTML entities.

## 1.3.1
- Исправлена коммерческая аналитика: KPI считаются только по завершённым заказам клиентов.
- Ручные складские движения sale/return больше не искажают количество проданных единиц, выручку и топ товаров.
- Метрика в Telegram переименована в «Продано по завершённым заказам».
- Усилен системный промпт: gross_profit всегда называется валовой, а не чистой прибылью.
- Добавлены регрессионные тесты для старых ручных движений склада.


## 1.3.0

- Добавлены отдельные сущности поставщиков.
- Добавлены закупочные заказы и автоматическая приёмка на склад.
- Добавлены заказы клиентов и атомарное завершение продажи.
- Добавлены снимки цены продажи и себестоимости в новых sale/return движениях.
- Добавлена аналитика: выручка, себестоимость, валовая прибыль, маржа и топ товаров.
- Добавлен business dashboard склада, продаж, закупок и поставщиков.
- Добавлены Telegram-команды `/dashboard`, `/analytics`, `/suppliers`, `/purchases`, `/sales` и операции документов.
- Добавлены автоматические уведомления о новом дефиците и ежедневный dashboard администраторам.
- Роли AI расширены на закупки и заказы с обязательным подтверждением write-tools.
- Исправление structured list responses MCP включено в основной `mcp_client.py`.
- Миграция v1.2.0 → v1.3.0 сохраняет существующие товары, остатки, историю и `.env`.
